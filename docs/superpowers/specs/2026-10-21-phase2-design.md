# 2단계 설계: 직원 12명 · 일정 · 오늘 할 일 · 공부모드 · PC/폰 알림

2026-10-21. ritual의 요청(자리 비움, "질문하지 마"): 기능을 크게 늘리고, 직원 수를 늘리고, 일정·오늘 할 일·공부모드를 넣고,
알림은 PC와 폰 둘 다 시스템 알림으로, 그리고 정말 잘 되는지 확실히 검증.
질문을 받을 수 없어서 아래의 모든 결정은 **내 판단(Claude의 결정)** 이다. 1단계 설계(`2026-10-21-ritual-study-office-design.md`)의 원칙은 그대로:
로컬 qwen3.5, 인터넷은 필요한 곳만, 픽셀 아트, 브라우저 대화상자 금지.

## 목표

1. 직원 6명 → 12명 (책상 4×3). 새 직원은 각자 진짜 일을 한다.
2. 오늘 할 일(체크리스트), 일정(달력·D-day), 공부모드(집중 타이머·공부 기록).
3. 알림: 일정·할 일 알림, 공부모드 끝, 작업 완료, 아침 브리핑 → PC(Windows 토스트) + 폰(ntfy 앱 푸시).
4. 말로도 된다: "내일 3시 수학 학원 일정 넣어줘", "시험 11월 20일인데 공부 계획 짜줘", "25분 공부모드 켜줘".
5. 결과물에서 이어서 하기: 카드의 [이 자료로 더 하기] → 문제·암기카드·마인드맵·질문.

비목표: 이미지 생성·영상(3단계), 계정·동기화, 여러 사용자. 반목표: 내가 켜지 않은 외부 전송(폰 알림은 사용자가 설정에서 켤 때만).

## 새 직원

| 역할 키 | 이름 | 하는 일 | 결과 |
|---|---|---|---|
| researcher | 조사원 | 주제를 한국어 위키백과에서 조사 (문학 작품이 아닌 개념·인물·사건) | 자료(Material) |
| tutor | 선생님 | 질문에 답한다. 자료가 있으면 자료 근거로 | `answer.md` + 카드에 답변 |
| cards | 암기담당 | 암기카드 (앞/뒤) 웹 + Anki용 CSV | `cards/index.html`, `cards.csv` |
| mapper | 정리왕 | 개념 마인드맵 웹 (방사형, 인쇄 가능) | `mindmap/index.html` |
| secretary | 비서 | 말로 한 일정·할 일을 정리해 등록, 알림 담당 | 플래너에 항목 추가 |
| coach | 코치 | 공부모드 타이머, 시험 대비 공부 계획(날짜별 할 일) | 플래너에 항목, 집중 세션 |

## 실장(라우터) 확장

단계: 자료 `scan · literature · research`, 결과 `pdf · quiz · cards · mindmap · answer`, 행동 `schedule · plan · focus`.
필드 추가: `topic`(조사 주제), `question`(질문 원문), `card_count`, `focus_minutes`, `use_last`(방금 자료로).
규칙(코드에서 강제): 결과 단계는 자료가 필요 (answer는 자료 없이도 됨) → 자료가 없으면 `use_last`/화면의 `ref`로 이전 작업 자료를 쓰고, 그것도 없으면 되묻기.
조사만 시키면 pdf를 붙인다. 작업 제목은 스캔한 프린트의 첫 제목·작품 이름을 우선 (1단계 최종 검토의 미뤄둔 항목).

## 플래너 (`output/planner.json`)

- 할 일: `{id, text, date, time, done}` — 오늘 화면은 오늘 것 + 지난날 못 한 것(“밀린 일”, [오늘로] 버튼).
- 일정: `{id, title, date, time, kind(일정|시험|숙제), remind(분 전, 없으면 null), repeat(none|daily|weekly)}` — 시험은 헤더에 D-day.
- 공부모드: `{running: {kind(focus|break), task, start, end} | null, log: [{date, minutes, task}]}` — 오늘 공부 시간, 7일 막대, 연속 공부 일수.
- 서버가 15초마다 확인해서 때가 된 알림을 보낸다. 같은 알림은 한 번만(`fired`), 꺼져 있던 동안 지난 알림은 10분 안의 것만 보낸다.
- 아침 브리핑(기본 07:30): 오늘 일정·할 일 개수와 가장 가까운 D-day.

## 알림 (`office/notify.py`)

- PC: Windows 토스트. 앱 ID `Ritual.StudyOffice`를 `HKCU\Software\Classes\AppUserModelId`에 등록(이름·아이콘) → PowerShell로 토스트. 글자는 XML 이스케이프 후 환경 변수로 넘긴다(명령어 주입 방지). 확인함: 등록 후 토스트가 알림 센터 기록에 남음.
- 폰: [ntfy](https://ntfy.sh) — 무료, 계정 없음. 설정에서 [폰 알림 켜기] → 추측 불가능한 주제 이름 생성 → QR(주소)과 앱 설치 안내 → [테스트 알림]. JSON으로 보내 한글 제목이 깨지지 않게. 서버 주소는 바꿀 수 있음(직접 운영하는 ntfy).
- 설정(`output/settings.json`): PC 켬/끔, 폰 켬/끔·주제·서버, 작업 완료 알림, 아침 브리핑 시각.
- 한계: PC가 꺼져 있으면 알림도 없다 → 설치 시 Windows 시작할 때 사무실 서버가 창 없이 켜지도록(시작프로그램 바로가기).

## 화면

- 사무실 4×3 책상. 책상 앞판이 이름표(높이 절약). 새 직원 6명 픽셀 캐릭터.
- 오른쪽 패널 탭: 보관함 / 오늘 / 일정 / 설정.
- 헤더: 가장 가까운 시험 D-day, 오늘 공부 시간, [공부모드].
- 공부모드 덮개: 큰 픽셀 타이머, 할 일 고르기, 25·50분 / 쉬기 5·10분, 그만. 서버가 시간을 재서 창을 닫아도 알림이 온다.
- 보관함: 검색, [이 자료로 더 하기], 에러 작업 [다시], [지우기](두 번 누르기), 결과 버튼 추가(암기카드·마인드맵·CSV·답변).

## 검증

- 단위 테스트: 플래너(시간 주입), 알림(실행기 주입), 새 직원(가짜 LLM), 라우터, 작업 흐름, API.
- 화면 E2E: Playwright + 설치된 Edge(`channel="msedge"`, 브라우저 다운로드 없음)로 가짜 직원 서버를 띄워 클릭·입력·드래그까지.
- 실측: 실제 qwen3.5로 새 직원 전부(조사·답변·암기카드·마인드맵·일정 말하기·공부 계획), PC 토스트 기록 확인, ntfy 테스트 메시지 왕복(내용은 "테스트"뿐).
- 하지 않는 것: Vercel 실제 배포(공개 링크가 생김 — ritual이 돌아와서 직접).

## 추가 요청: 대표실과 최종 결재 (같은 날 추가)

ritual: "대표실도 만들고 최종 대표 승인이 있어야 마무리 되도록, 권한 자동 허용도, 진짜 상업적으로".
ritual = 대표. 결과물이 생긴 작업은 **결재 대기**가 되고, 대표가 승인해야 **완료**가 된다.

- 작업 상태: 대기 → 진행 중 → **결재 대기** → 완료(승인) / **수정 중**(반려) → 결재 대기 … / 에러 / 되물음.
  결과물이 없는 작업(인사, 일정 등록, 공부모드)은 결재 없이 바로 완료.
- 반려: 대표가 수정 요청을 적으면 같은 자료로 결과물을 다시 만든다. 직원 프롬프트에 "대표 수정 요청"이 들어간다. 몇 번째 수정인지, 결재 기록(누가·언제·의견)이 남는다.
- 배포(공개 링크)는 승인된 작업만.
- **자동 승인 규칙**(내 해석: "권한 자동 허용" = 대표가 결재 권한을 실장에게 위임): 결과물 종류별로 켬/끔. 기본값은 답변만 자동 승인, 나머지는 대표 결재. 자동 승인된 작업은 기록에 "자동 승인"으로 남는다.
  (Claude Code 자체의 권한 프롬프트는 이 세션이 이미 자동 모드라 따로 건드리지 않음.)
- 결재 요청이 오면 PC·폰 알림 "결재 요청: <제목>".
- 대표실 화면(덮개): 결재함(미리보기 + 승인/반려), 회사 현황(오늘 처리·결재 대기·승인율·이번 주 공부 시간·직원별 실적), 자동 승인 규칙, 결재 이력.
  사무실 바닥에는 대표실 문이 있고 결재 대기 수가 빨간 배지로 뜬다.
- 상용 마감: 화면 안 토스트 메시지, 첫 실행 안내, 빈 화면 안내, 단축키, 데이터 백업(zip), 버전 정보.

## 추가 요청: 폰에서 작업 시키고 파일 받기 (같은 날 추가)

ritual: "내 폰 사이트에서 작업을 시키고 그 파일을 가져올 수 있도록".

- 폰 전용 페이지 `/m`: 명령 + 사진 찍어 올리기(카메라) + 작업 목록·진행 상태 + 결과 내려받기(PDF·문제·암기카드·마인드맵·답변) + 결재(승인/반려) + 오늘 할 일 체크.
- 원격 서버는 따로: 포트 8766, **모든 요청에 토큰 필요**(처음 `?k=토큰`으로 들어오면 HttpOnly 쿠키). 내 PC 화면용 8765는 지금처럼 로컬 전용·토큰 없음.
- 연결 방식(설정에서 선택, 기본 끔 — 내 PC를 인터넷에 여는 일이라 대표가 직접 켠다):
  - 같은 와이파이: `0.0.0.0:8766` (처음 켤 때 Windows 방화벽 허용 창이 뜰 수 있음).
  - 어디서나: Cloudflare 무료 임시 터널(`cloudflared`, 계정 없음, 켤 때 내려받음) → `https://….trycloudflare.com` 주소. 주소가 켤 때마다 바뀌므로 새 주소를 폰 알림으로 보낸다.
- 설정 화면에 접속 QR, [토큰 바꾸기](이전 링크 무효화).

## 추가 요청: 모든 파일 분석 · 탭 나누기 · 전문화된 사무실 (같은 날 추가)

ritual: "모든 파일을 분석 가능하고, 탭을 나눌 수 있도록, 좀 더 전문화된 사무실". 질문을 받을 수 없어서 아래 해석도 내 판단이다.

- **모든 파일 읽기 (스캐너)**: 사진(JPG·PNG·WEBP·BMP·GIF·TIFF), PDF, 한글(HWP·HWPX), 워드(DOCX), 파워포인트(PPTX), 엑셀(XLSX),
  텍스트류(TXT·MD·CSV·JSON·HTML·코드 등 글자 파일). 문서는 AI 없이 글자를 바로 꺼낸다(빠르고 정확, 표는 `칸 | 칸`).
  HWP는 `olefile`로 본문을 직접 읽는다 — 암호·배포용 문서는 안내. 옛 형식(.doc·.ppt·.xls), 소리·영상(3단계), HEIC는 이유와 바꾸는 법을 알려준다.
- **분석가(analyst)** 새 직원: 어떤 자료든 분석 보고서 웹 — 자료 종류·과목·난이도, 한 줄 요약, 핵심 내용, 핵심 개념, 시험 포인트,
  헷갈리는 부분, 공부 방법·예상 공부 시간. 파일만 올리고 할 일을 말하지 않으면 분석한다.
- **번역가(translator)** 새 직원: 번역 웹(원문 | 번역 나란히, 인쇄 가능). 언어를 말하지 않으면 한국어 자료는 영어로, 외국어 자료는 한국어로.
- **전문화**: 직원 14명을 4개 팀으로 — 경영지원팀(실장·비서·배포담당), 자료조사팀(스캐너·사서·조사원·분석가),
  콘텐츠제작팀(디자이너·출제위원·암기담당·정리왕), 학습지원팀(선생님·번역가·코치). 사무실 바닥은 팀 구역·팀 팻말·대표실 문,
  작업마다 작업 번호, 결재 도장(승인·반려), 대표실에 조직도와 직원별 실적.
- **탭 나누기**: 화면을 탭으로 — 사무실 · 보관함 · 오늘 · 일정 · 대표실 · 설정. [나눠 보기]를 켜면 두 탭을 나란히(왼쪽·오른쪽이 각자 탭을 고름, 넓은 화면에서).
  마지막 배치는 브라우저에 기억. 명령 바는 늘 아래.

## 추가 요청: 특정 직원에게 시키기 · 작업 중단 · 초기화 · 편의 기능 · 작업 히스토리 (같은 날 추가)

ritual: "특정 사람한테 작업을 실행시킬 수 있고, 작업 중단·초기화 등 여러 부가 기능을 편리하게", "보관함에서 내 작업 히스토리를 볼 수 있게". 해석은 내 판단.

- **직원 지정**: 지시 앞에 `@이름`(예: `@번역가 이거 일본어로`) 또는 사무실에서 책상을 누르면 `@이름`이 지시 칸에 들어간다.
  실장은 그 직원의 일만 고른다(필요한 자료 단계는 붙임). 직원별 일: 비서=일정, 스캐너=파일 읽기, 사서=작품, 조사원=조사, 분석가=분석,
  디자이너=PDF, 출제위원=문제, 암기담당=암기카드, 정리왕=마인드맵, 선생님=답변, 번역가=번역, 코치=공부 계획·공부모드. 실장=평소대로, 배포담당=버튼 안내.
  카드에 "담당: 이름".
- **중단**: 대기 중 작업은 바로 취소, 하는 중인 작업은 지금 단계가 끝나는 대로 멈춤(상태 "취소됨", 만든 결과물은 남김). 고치던 작업을 멈추면 결재 대기로 돌아감. [모두 중단].
- **초기화**: 작업마다 [처음부터 다시](같은 명령·파일로 새로). 설정 탭 "초기화": 직원 자리 정리, 대기열 비우기, 보관함 정리(완료·에러·취소 작업 지움, ★와 결재 대기는 남김), 완료한 할 일 지우기, 설정 기본값(폰 주제는 유지), 화면 배치·안내 초기화. 전부 두 번 눌러야 실행.
- **편의**: 지시 칸 위 빠른 명령 버튼, ↑↓로 이전 명령, [고쳐서 다시](명령을 지시 칸에 다시 넣고 그 자료를 고른 상태로), ★ 즐겨찾기, 제목 바꾸기, 결과 한 번에 받기(zip), 대기 순번 표시. 폰에서도 중단·zip.
- **작업 히스토리**: 보관함 [최근 | 전체 기록]. 전체 기록은 지난 작업 전부(날짜별 묶음, 검색·상태·★ 필터, 30개씩 더 보기). 옛 작업에서도 결과 열기·이 자료로 더 하기·★·지우기가 된다.

## 추가 요청: 실장이 직접 행동하는 에이전트 (같은 날 추가)

ritual: "실장한테 내 폰으로 굿나잇이라고 보내라니까 안 되네. 텍스트만 만드는 게 아니라 에이전트로서 동작하게".
지금 실장은 단계(직원 일)만 고르고, 고를 단계가 없으면 말로만 대답한다. → 실장이 **바로 하는 일(actions)** 을 고르고, 코드가 그대로 실행한다.

- 한 번의 판단(JSON, 형식 강제)으로 단계 + 행동을 같이 고른다 — 작은 모델(4B)에서 도구 호출 대화보다 안정적이고 빠름(내 판단).
- 행동: `notify`(폰·PC·둘 다로 메시지) · `remind`(몇 분 뒤/몇 시에 알림) · `today`(오늘 할 일·일정·D-day 알려주기) · `jobs`(작업·결재 현황)
  · `approve`/`reject`(결재, 방금 것·전부·번호) · `cancel`(중단) · `rerun`(처음부터 다시) · `todo_done`(할 일 체크) · `focus_stop` · `setting`(AI 모드·알림·브리핑).
- 실행 결과는 실장 대답에 붙인다("폰으로 '굿나잇' 보냈어"). 알려주기(today·jobs)는 실제 데이터로 대답을 만든다(지어내지 않게).
- 폰이 꺼져 있으면 "설정에서 폰 알림을 켜줘"처럼 할 수 없는 이유를 말한다. 지우기 같은 되돌릴 수 없는 일은 행동에 넣지 않는다(화면 버튼으로만).
