# ritual의 공부 사무실 — 설계서

> 작성 2026-10-21 · 1단계 구현 계획: `docs/superpowers/plans/2026-10-21-ritual-study-office-phase1.md`

## 1. 한 줄 요약

내 노트북에서 돌아가는 로컬 AI 직원들이 학교 프린트와 문학 작품을 **디자인된 PDF 노트**와 **문제 풀이 웹(Vercel 배포)** 으로 바꿔주는 픽셀 아트 사무실 프로그램. 바탕화면 아이콘을 누르면 실행된다.

## 2. 왜, 누구를 위해

- **사용자**: ritual 한 명. 문제 웹은 친구들과 나눌 수 있게 공개 배포한다 (공유 대상은 추측).
- **계기**: 학교에서 받은 A4 정리 프린트를 공부하기 좋은 형태로 다시 만드는 손작업을 AI한테 맡기고 싶다.
- **성공 기준**
  - 프린트 사진·스캔을 올리고 한 줄 명령 → 손대지 않아도 PDF 노트가 나온다.
  - "문제 만들어서 배포해" → 친구에게 보낼 공개 링크가 나온다.
  - "<작품명> 가져와" → 원문(저작권 끝난 작품)과 해설 노트가 나온다.
  - 작업이 이어진다: 작품 가져오기 → 문제 웹.

## 3. 목표 · 비목표 · 안티목표

**목표 (1단계)**
- a. 프린트(사진·스캔 PDF) → 디자인된 PDF 노트
- b. 프린트·자료 → 문제 풀이 웹 → Vercel 배포
- c. 문학 작품 가져오기 (원문 + 해설 노트)
- 픽셀 아트 사무실 화면: AI 직원들이 일하는 모습이 보인다
- 바탕화면 아이콘 더블클릭으로 실행, 명령어 입력 불필요

**비목표 (1단계에선 안 함 → 7. 로드맵)**
- 이미지 생성, 영상 제작
- 로컬 모델이 앱을 통째로 짜는 자유 바이브코딩
- OCR 결과를 손으로 고치는 편집 화면
- 여러 사용자, 로그인, 휴대폰 앱

**안티목표 (이러면 실패)**
- 프린트에 없는 내용을 AI가 지어내 노트·문제에 넣는다
- 내 확인 없이 공개 배포가 일어난다
- 저작권이 살아 있는 작품의 원문을 공개 사이트에 올린다
- 작업 하나가 실패했다고 프로그램 전체가 죽는다
- 실행하려면 명령어를 쳐야 한다

- 위 속도는 추정이다. 1단계 마지막 작업에서 실제로 재서 README에 적는다.

## 5. 어떻게 동작하나

**직원 (역할 = 지시문 + 코드 단계)**

| 직원 | 하는 일 | AI 사용 |
|---|---|---|
| 실장 | 명령 해석 → 작업 순서 결정 → 진행 보고. 재료가 없으면 되묻는다 | qwen3.5 (JSON 응답) |
| 스캐너 | 사진·스캔 PDF → 글자. 글자가 들어 있는 디지털 PDF는 바로 추출 | qwen3.5 그림 인식 |
| 사서 | 위키문헌(저작권 끝난 원문) + 위키백과(해설 자료) → 작품 공부 노트 | qwen3.5 |
| 디자이너 | 자료 → 노트 구조(JSON) → 픽셀 포인트 HTML → PDF | qwen3.5 + Edge |
| 출제위원 | 자료 → 객관식·OX·단답 문제 → 문제 풀이 페이지 | qwen3.5 |
| 배포담당 | 내가 [배포]를 누르면 문제 사이트를 Vercel에 올리고 공개 링크를 준다 | 없음 (코드만) |

**흐름 예**
- "이 프린트 PDF로 만들어줘" + 사진 2장 → 실장 `[scan, pdf]` → 스캐너 → 디자이너 → 결과 보관함에 PDF.
- "운수 좋은 날 가져와서 문제 10개" → 실장 `[literature, quiz]` → 사서 → 출제위원 → 미리보기 → 내가 [배포] 두 번 클릭 → 배포담당 → 공개 링크.

**화면 (픽셀 아트)**
- 창: Edge 앱 모드 (주소창 없는 독립 창).
- 위: 픽셀로 만든 ritual 로고, "공부 사무실", AI 연결 상태 표시등, [퇴근] 버튼.
- 가운데: 사무실 바닥에 책상 6개, 직원 픽셀 캐릭터(16×16을 4배 확대). 상태: 대기 / 일하는 중(타자 애니메이션 + 말풍선) / 완료 / 에러.
- 오른쪽: 결과 보관함 (PDF 열기, 문제 미리보기, 텍스트 보기, 폴더 열기, 배포).
- 아래: 업무 일지(직원들 대화 기록) + 명령 입력창(파일 첨부·끌어다 놓기).
- 색: 로고에서 뽑은 6색 `#9337FD #E036F0 #FC34CA #FD389C #FD633E #FC7135` + 어두운 남보라 바탕. 글꼴: Galmuri11 (한글 픽셀 폰트, OFL 라이선스).
- PDF 노트와 문제 웹도 같은 픽셀 포인트를 쓴다. 제목·장식은 픽셀, 긴 본문은 읽기 쉬운 맑은 고딕.

**실행**
- 바탕화면 "ritual의 공부 사무실" 아이콘(로고의 r을 픽셀로 만든 아이콘) 더블클릭 → 콘솔 창 없이 → Ollama 확인(꺼져 있으면 켬) → 사무실 서버 시작 → 앱 창이 열린다.
- 이미 켜져 있으면 창만 다시 연다. 끌 때는 화면의 [퇴근] 버튼.

## 6. 결정 사항

**ritual이 정한 것**
- 이름 "ritual의 공부 사무실", 로컬 AI 여러 명이 함께 일하는 구조
- 1단계 범위 a·b·c
- 픽셀 아트 디자인, 로고 `ritual-wordmark-transparent.png`
- 바탕화면 아이콘으로 실행
- 모델 하나가 역할을 바꿔 가며 일하는 방식 (8GB 제약 설명 듣고 동의)

**내가 정한 것 (바꾸고 싶으면 말하기)**
- Python + FastAPI 로컬 서버 + 웹 화면을 Edge 앱 창으로 띄운다. Electron 같은 앱 프레임워크는 안 쓴다.
- 문제 웹은 미리 만든 틀에 AI가 문제 데이터만 채운다. AI가 코드를 짜지 않는다.
- 배포는 항상 내가 직접 누른 뒤에만. 배포 사이트는 하나(`ritual-quiz`)이고 문제마다 주소가 하나씩 생긴다 (`/q/<작업번호>/`). 배포를 누른 문제만 사이트에 들어간다.
- 문학 원문은 위키문헌에 있는 것만 가져온다 (= 저작권 끝난 작품). 없으면 위키백과 기반 해설만.
- 결과물은 프로젝트의 `output/` 폴더 (OneDrive라 폰에서도 PDF가 열림). 가상환경·로그·브라우저 프로필은 OneDrive 밖 `%LOCALAPPDATA%\ritual-office`.
- 서버는 이 PC(127.0.0.1)에서만 접속된다.
- 생각 모드(thinking)는 끈다. 속도 우선.
- 디지털 PDF는 글자를 바로 꺼내고, 사진·스캔본만 AI로 읽는다.

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 다른 앱이 GPU를 써서 VRAM 부족 → 느려짐 | 게임·브라우저 하드웨어 가속 끄기. 작업 시간 표시 |
| OCR 오타, 손글씨 | 읽은 글자(`source.txt`)를 같이 저장. 편집 화면은 후보 |
| AI가 내용을 지어냄 | 지시문에 "자료에 없는 내용 금지", 해설엔 출처 링크, 낮은 temperature |
| 자료가 너무 김 (8,000자 초과) | 앞부분만 쓰고 화면에 경고. 나눠 처리는 나중 |
| 휴대폰 사진이 옆으로 누움, 아이폰 HEIC | 사진 회전 정보대로 세움. HEIC는 안내 메시지 |
| Vercel 로그인 필요 | 설치할 때 `vercel login` 한 번 |
| 배포별 주소엔 로그인 벽이 있음 | 프로젝트 기본 주소(가장 짧은 `*.vercel.app`)를 공유 |
| OneDrive 동기화가 가상환경 파일을 잠금 | 가상환경을 OneDrive 밖에 둠 |
| 한글·공백이 든 프로젝트 경로 | PDF 변환 테스트를 한글 폴더에서 돌림 |
